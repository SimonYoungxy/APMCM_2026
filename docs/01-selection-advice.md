# 选题建议（可直接复制发队友）

2026 APMCM 四题选题分析建议

一、数据核查事实（实际打开数据包确认，非题面描述）

A 题 洪水遥感：
- 附件 1 为 1000 组 256×256 三联样本：灾前光学 RGBA、灾后 SAR 单波段 uint8、二值标签（0/1），解压约 395 MB。
- 训练集完整可用，但第 3 问起需要自己到 Copernicus 等平台下载恒州（Hengzhou）灾前/灾中影像，第 4 问还要人口、建筑、路网、医院、避难所、地形数据，并自行确定空间评估单元。

B 题 转炉炼钢：
- 10 个 .xlsb 文件，每个约 1400 行 × 2051 列（1 列序号 + 2047 个波长 + 累积氧耗 + CO₂ 浓度 + CO 浓度），压缩后 106 MB，展开后数值量约 2.9 亿个。
- 数据全在包内，不需要任何外部数据；但需要 pyxlsb 转换，内存占用高。
- 注意：表头实际波长范围是 339.39–1023.303 nm，与题面写的 340.535–1027.678 nm 不一致，写作时需说明。

C 题 企鹅声学：
- Data01 声学特征 108 行 × 11 列；Data02 回放实验 278 行 × 40 列；Data03–11 各 300 行 × 7 列（三种 call × 三种指标）；另附 3 段 wav 和 2 份官方 R 分析代码。
- 全部为清洗好的 CSV，零清洗成本。
- 关键结构：F02（第二基频）只在 tv 类有值（24/24），flat 和 mod 全缺（0/44、0/40）；PulseRate 在 flat 类完全没有（0/44）。也就是“有无第二基频”就是 two-voice 的定义，直接喂进分类器会得到 100% 数据泄漏。
- 回放事件数：任何响应 108、抬头 68、发声 81、接近仅 23；Distance 有 13 个水平且与 CallType 交叉后存在 9 个空格，交互项不可估。

D 题 量子选材：
- 训练集 11,256 行 + 验证集 3,969 行，共 15,225 行 × 22 列；测试集 3,703 行完全无标签。
- 致命细节：训练+验证的 15,225 个样本里，V=0 的样本数是 0，满足四条物理条件的也是 0；题面说的 19 个正样本全在无标签的 holdout 里。第 1 问因此是“零正样本 + 极端外推排序”，不是普通回归。
- 第 2、3 问要走 Kaiwu SDK 建模求解，并需申请 SPQC 量子算力，涉及注册与额度。

二、逐题点评

A 题
- 优点：第 1、2 问非常标准，1000 张带标签小图，U-Net 一类分割模型直接能跑；题面已明确规定要报新增淹没面积误差、相对面积误差、空间重叠度，评价口径清晰。
- 问题：第 3 问起要自己找 2026 年 7 月恒州的灾前/灾中影像，做跨传感器几何配准，再叠加人口、建筑、路网、避难所、DEM。配准误差会直接让“新增淹没面积”这个核心数字失去意义，而且这部分评分主观、几乎无法自证。
- 结论：除非队里有遥感/GIS 经验，否则不推荐。

B 题
- 优点：数据自洽、不需要外部数据；第 1、2 问是离群点剔除 + 连续重构 + 三维频谱图 + 互相关估时延，性价比极高，而且“流速越大时延越小”这条给了现成的验证信号。
- 问题：第 3 问是真正的硬活——用 2047 维火焰光谱实时预测 CO₂/CO，还要求跨 10 个炉次泛化。每炉只有约 1400 个时间点，跨炉域偏移明显，需要 PyTorch 与 GPU，调参周期长。
- 结论：队里有深度学习经验和 GPU 就选它，否则第 3 问会拖垮全篇。

C 题
- 优点：数据小、干净、全部现成；官方还给了一份 R 代码，等于把“标准分析路径”交到手里；四问正好对应描述统计 → 非参数检验 → 分类器 → 单调衰减模型 + 阈值反解 + Bootstrap → GLM/多项分布/生存分析，是一条完整且标准的统计流水线，AI 写代码几乎零阻力，抽象材料几乎没有。
- 问题：容易同质化，几乎每支队伍都会做“描述统计 + Kruskal-Wallis + 随机森林”这一套；想出彩必须靠统计深度，例如把“无响应”当右删失做生存分析、用 Bootstrap 给通信半径置信区间、把 F02/PulseRate 的结构性缺失讲成机理而不要当成特征。
- 结论：最稳、最容易完整交付，符合“AI 好处理 + 容易上手 + 少抽象”的全部要求。

D 题
- 优点：创新性最强，第 1 问就是标准表格回归（LightGBM/XGBoost 即可），AI 处理数据毫无压力；做出来的人少，容易靠“别人做不出来”拿高分。
- 问题：风险与收益同源——零正样本回归、V 重尾、需要把非线性代理模型二次化成 QUBO、还要满足量子硬件系数约束、还要申请算力。文档以中文社区为主，环境搭不起来就直接卡死。
- 结论：想赌创新、且队里有人愿意专门啃 SDK 才选；否则不碰。

三、按三条标准打分（高/中/低）

AI 能代劳数据处理：
A 高 ｜ B 中 ｜ C 极高 ｜ D 高（仅第 1 问）

上手难度（越低越好）：
A 中（前两问易、后三问难）｜ B 中高 ｜ C 最低 ｜ D 高

外部依赖风险：
A 高（自采遥感 + 多源空间数据）｜ B 低 ｜ C 无 ｜ D 高（SDK / 算力 / 审批）

抽象材料占比：
A 中（优化模型）｜ B 较低 ｜ C 最低 ｜ D 最高（QUBO 重构 + 系数约束）

完成度风险：
A 高 ｜ B 中 ｜ C 最低 ｜ D 高

创新出彩空间：
A 中 ｜ B 中高 ｜ C 中 ｜ D 最高

四、结论与选择规则

首选 C 题。它几乎完全符合你的三条要求：数据全给你、规模小到可以反复迭代、官方 R 代码等于标准答案骨架、四问都是标准统计方法、几乎没有抽象推导。唯一短板是同质化，需要用统计深度拉开差距——把 Q3 的“无响应”当右删失做生存分析、Q2 用 Bootstrap 给通信半径置信区间、Q1 明确处理 F02/PulseRate 的结构性泄漏，就足够区别于普通队伍。

次选 B 题。前提是队里有 PyTorch 经验和 GPU。第 1、2 问能快速出漂亮结果，第 3 问才是真正的时间成本。

D 题只在两种情况下选：队里有人愿意专门啃 Kaiwu SDK 与算力申请，并且接受第 2、3 问可能只做出简化版。

A 题不推荐，除非队里有遥感或 GIS 背景。

一句话规则：
- 想稳、想完整交付、想少碰抽象推导 → C
- 有深度学习与 GPU、想写技术含量更高的论文 → B
- 想赌创新、能接受高风险 → D
- 有遥感背景 → A，否则排除
